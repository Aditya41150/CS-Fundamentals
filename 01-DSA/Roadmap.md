# DSA Roadmap — Interview First

Use this roadmap to decide **what to learn and practice**. Do not try to finish every DSA PDF.

## Study Order

### 1. Foundations
- Time and space complexity
- Arrays and strings
- Basic recursion
- Sorting basics
- Hashing

Recommended references:
- [DSA Cheatsheet](../DSA/DSA-Cheatsheet.pdf)
- [DSA Resource](../DSA/DSA-Resource.pdf)

### 2. Core Patterns
- Two pointers
- Sliding window
- Prefix sum
- Binary search
- Stack and queue patterns
- Hash map / frequency counting

For each pattern: understand the idea → solve 2 easy problems → solve 2–3 medium problems → write down mistakes.

### 3. Linked Lists
- Traversal
- Reverse a list
- Fast/slow pointers
- Cycle detection
- Merge lists
- Basic linked-list interview questions

### 4. Trees
- Binary trees
- DFS / BFS
- Preorder, inorder, postorder
- Level-order traversal
- Height / depth
- BST basics
- Common tree recursion

### 5. Recursion and Backtracking
- Subsets
- Permutations
- Combination-style problems
- N-Queens style reasoning

### 6. Graphs
- Graph representation
- BFS / DFS
- Connected components
- Cycle detection
- Shortest-path basics
- Topological sort basics

### 7. Greedy
- Recognizing greedy choices
- Sorting-based greedy problems
- Interval problems

### 8. Dynamic Programming
- 1D DP
- 2D/grid DP
- Include/exclude patterns
- Memoization vs tabulation
- Recognize when DP is appropriate

### 9. Interview Practice
Use these after the fundamentals are understood:
- [Striver SDE Sheet Solutions](../DSA/Striver-SDE-Sheet-Solution.pdf)
- [Top 50 DSA Interview Questions](../DSA/Top-50-DSA-Interview-Questions.docx)
- [LeetCode Problems](../LeetCode-Problems.pdf)

## How to Study a DSA Topic

1. Learn the pattern, not just one solution.
2. Close the resource.
3. Explain the approach aloud.
4. Solve a problem without looking at the solution.
5. If stuck, study the hint/solution, close it, and re-code it yourself.
6. Record the mistake.
7. Re-attempt the problem later.

## Do Not Move On When

You can only solve one memorized example, cannot explain the complexity, or cannot recognize when the pattern applies.

## Interview-Ready Test

Given an unseen problem, you should be able to clarify the problem, propose a brute-force idea, improve it, explain time/space complexity, and write clean code.
